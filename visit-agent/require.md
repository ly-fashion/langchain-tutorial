# 旅游助手 Agent 需求文档

> 基于 LangChain 的智能旅游助手系统

---

## 一、项目概述

### 1.1 项目目标
开发一个功能完善的智能旅游助手 Agent，能够帮助用户规划旅行、查询信息、提供建议。

### 1.2 核心价值
- 智能对话：自然语言交互
- 信息整合：多源数据聚合
- 个性推荐：基于偏好定制
- 行程规划：自动化规划

---

## 二、功能需求

### 2.1 目的地信息查询

#### 2.1.1 基础信息
| 功能 | 描述 | 优先级 |
|------|------|--------|
| 城市介绍 | 城市概况、特色、文化 | P0 |
| 景点查询 | 热门景点、开放时间、门票 | P0 |
| 天气查询 | 实时天气、天气预报 | P0 |
| 时区查询 | 当地时间、时差 | P1 |
| 汇率查询 | 货币兑换、汇率计算 | P1 |
| 签证信息 | 签证要求、办理流程 | P1 |
| 语言信息 | 当地语言、常用短语 | P2 |

#### 2.1.2 详细信息
```
景点详情:
- 名称、地址、坐标
- 开放时间、门票价格
- 游览时长建议
- 用户评分、评价摘要
- 交通方式
- 最佳游览时间
```

### 2.2 行程规划

#### 2.2.1 智能规划
| 功能 | 描述 | 优先级 |
|------|------|--------|
| 行程生成 | 根据天数、偏好生成行程 | P0 |
| 行程优化 | 优化路线、减少交通时间 | P0 |
| 多日规划 | 支持多天行程安排 | P0 |
| 灵活调整 | 用户可修改、调整行程 | P1 |
| 备选方案 | 提供备选景点和路线 | P2 |

#### 2.2.2 规划参数
```
输入参数:
- 目的地
- 出发日期、结束日期
- 旅行人数（成人/儿童/老人）
- 预算范围
- 兴趣偏好（自然/历史/美食/购物/冒险）
- 体力水平（轻松/适中/挑战）
- 特殊需求（无障碍、宠物友好）

输出内容:
- 每日行程安排
- 景点游览顺序
- 交通方式建议
- 餐饮推荐
- 住宿建议
```

## 三、技术需求

### 3.1 Agent 架构

#### 3.1.1 核心组件
```
┌─────────────────────────────────────────────┐
│              旅游助手 Agent                   │
├─────────────────────────────────────────────┤
│  LLM Core        │ 核心语言模型               │
│  Memory          │ 对话记忆系统               │
│  Tools           │ 工具集                     │
│  Prompt          │ 提示词模板                 │
│  Output Parser   │ 输出解析器                 │
└─────────────────────────────────────────────┘
```

#### 3.1.2 工具清单
| 工具 | 功能 | API来源 |
|------|------|---------|
| weather_query | 天气查询 | OpenWeatherMap |
| place_search | 地点搜索 | Google Places / 高德 |
| route_planning | 路线规划 | Google Directions / 高德 |
| hotel_search | 酒店搜索 | Booking / 携程 |
| flight_search | 航班搜索 | Skyscanner / 去哪儿 |
| restaurant_search | 餐厅搜索 | 大众点评 / Yelp |
| currency_convert | 汇率转换 | ExchangeRateAPI |
| web_search | 网络搜索 | SerpAPI / DuckDuckGo |
| knowledge_base | 知识库检索 | 向量数据库 |
| calculator | 计算器 | 内置 |

### 3.2 数据存储

#### 3.2.1 向量数据库
```
用途: 存储旅游知识、景点信息、用户偏好
方案: FAISS / Chroma / Milvus
内容:
- 景点描述和评价
- 旅游攻略
- 常见问题
- 用户历史对话
```

#### 3.2.2 结构化数据
```
用途: 存储用户信息、行程数据
方案: SQLite / PostgreSQL
表结构:
- users: 用户信息
- trips: 行程记录
- preferences: 用户偏好
- bookings: 预订记录
```

### 3.3 记忆系统

#### 3.3.1 短期记忆
```
类型: ConversationBufferWindowMemory
用途: 当前对话上下文
窗口: 最近10轮对话
```

#### 3.3.2 长期记忆
```
类型: ConversationSummaryMemory
用途: 对话摘要、用户偏好
持久化: 数据库存储
```

#### 3.3.3 实体记忆
```
类型: ConversationEntityMemory
用途: 提取关键信息（目的地、日期、人数）
```

### 3.4 提示词设计

#### 3.4.1 系统提示词
```
角色定义: 你是专业的旅游顾问助手
能力说明: 目的地推荐、行程规划、信息查询
行为规范: 友好专业、详细准确、主动询问
输出格式: 结构化、易读、包含来源
```

#### 3.4.2 提示词模板
```python
system_prompt = """
你是一个专业的旅游顾问助手，名叫「小旅」。

## 你的能力
1. 查询目的地信息（景点、天气、交通等）

- 使用清晰的标题和分段
- 重要信息使用列表

- 提供实用小贴士
"""
```

## 五、交互流程

### 5.1 典型对话流程
```
用户: 我想去北京旅游3天
  ↓
Agent: 好的！为了给您更好的建议，请告诉我：
  1. 出行时间是什么时候？
  2. 几个人一起去？
  3. 有什么特别想玩的吗？
  4. 预算大概多少？
  ↓
用户: 下周末，2个人，想看历史古迹，预算5000左右
  ↓
Agent: [调用工具查询]
  为您规划了北京3日游行程：
  Day 1: 故宫 → 天安门 → 王府井
  Day 2: 长城 → 鸟巢水立方
  Day 3: 颐和园 → 圆明园
  ...
```

### 5.2 Agent 决策流程
```
用户输入
  ↓
意图识别
  ├─ 信息查询 → 调用查询工具
  ├─ 行程规划 → 调用规划工具
  ├─ 闲聊对话 → 直接回复
  └─ 其他问题 → 搜索+生成
  ↓
工具调用
  ↓
结果整合
  ↓
生成回复
  ↓
更新记忆
```

## 九、风险与挑战

| 风险 | 影响 | 应对策略 |
|------|------|---------|
| API限流 | 功能不可用 | 缓存+降级 |
| 信息不准确 | 用户体验差 | 多源验证 |

| 隐私问题 | 法律风险 | 数据加密+脱敏 |
